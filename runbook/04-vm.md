## Purpose

Create one Generation 2 virtual machine for the house: Secure Boot, a vTPM, the blueprint CPU, memory and disk, and exactly one network adapter on the house switch.

## Before you start

The gate check must already pass. Open PowerShell as Administrator. Show every command in Do to the human and wait for approval before running it.

Attach the VM to `{{Network.SwitchName}}`. Never attach it to `Default Switch`. A second adapter would be a second way out of the house. Do not attach the Windows ISO as a DVD. Windows is applied offline in the next step, while the VM is Off.

Do not use `Set-VMKeyProtector -NewLocalKeyProtector`. That protector has caused "key protector could not be unwrapped" boot failures. Use the local HGS guardian below. The VM must be Off when the key protector and vTPM are enabled.

## Do

```powershell
New-VM -Name '{{House.Name}}' -Generation 2 -MemoryStartupBytes {{House.MemoryGB}}GB -Path '{{House.Path}}\{{House.Name}}' -NewVHDPath '{{House.Path}}\{{House.Name}}\{{House.Name}}.vhdx' -NewVHDSizeBytes {{House.DiskGB}}GB -SwitchName '{{Network.SwitchName}}'
Set-VMMemory -VMName '{{House.Name}}' -DynamicMemoryEnabled $false -StartupBytes ({{House.MemoryGB}} * 1GB)
Set-VM -Name '{{House.Name}}' -AutomaticCheckpointsEnabled $false
Set-VMProcessor -VMName '{{House.Name}}' -Count {{House.CpuCount}}
Set-VMFirmware -VMName '{{House.Name}}' -EnableSecureBoot On -SecureBootTemplate MicrosoftWindows
$guardian = Get-HgsGuardian -Name 'claude-house-guardian' -ErrorAction SilentlyContinue
if (-not $guardian) { $guardian = New-HgsGuardian -Name 'claude-house-guardian' -GenerateCertificates }
$keyProtector = New-HgsKeyProtector -Owner $guardian -AllowUntrustedRoot
Set-VMKeyProtector -VMName '{{House.Name}}' -KeyProtector $keyProtector.RawData
Enable-VMTPM -VMName '{{House.Name}}'
```

## Verify

Run:

```powershell
house check vm
```

A pass looks like `PASS vm: vm ready`.

## If it fails

- **exists:** No VM is named `{{House.Name}}`. Run the `New-VM` command in Do.
- **generation:** The VM is not Generation 2. Remove it only after the human agrees, then create it again with `-Generation 2`.
- **secureboot:** Secure Boot is not On, or the template is not `MicrosoftWindows`. Run the `Set-VMFirmware` command in Do while the VM is Off.
- **tpm:** `TpmEnabled` is not true. The VM must be Off. Create `claude-house-guardian` with `New-HgsGuardian -GenerateCertificates`, wrap it with `New-HgsKeyProtector -AllowUntrustedRoot`, pass that protector's `RawData` to `Set-VMKeyProtector`, then `Enable-VMTPM`.
- **cpu:** The processor count is not `{{House.CpuCount}}`. Run `Set-VMProcessor` from Do.
- **memory:** With dynamic memory on, the maximum must equal `{{House.MemoryGB}}` GB. With dynamic memory off, the startup value must equal that size. Run `Set-VMMemory` from Do.
- **staticMemory:** The VM must be Off. `(Get-VM).DynamicMemoryEnabled` must be `$false` and `MemoryStartup` must equal `{{House.MemoryGB}}` GB. Run `Set-VMMemory -VMName '{{House.Name}}' -DynamicMemoryEnabled $false -StartupBytes ({{House.MemoryGB}} * 1GB)`.
- **disk:** No attached VHD has a virtual `Size` of at least `{{House.DiskGB}}` GB. The new VHD path is `{{House.Path}}\{{House.Name}}\{{House.Name}}.vhdx`.
- **oneadapter:** The VM does not have exactly one network adapter. Remove the extra adapter. A second adapter is a second way out.
- **switch:** The single adapter is not on `{{Network.SwitchName}}`. `Default Switch` is never acceptable. Move the adapter to the house switch.
- **checkpoints:** Automatic checkpoints are on. Run `Set-VM -AutomaticCheckpointsEnabled $false`.
